# Contributing to fsspec-tools

The repository contains two independently released libraries, `vosfs` and
`fss-cli`, under `libs/`. Use uv for environments, dependencies, and project
commands. Work on a branch and keep each change focused.

## Set up

```bash
uv sync --locked --all-packages
uv run --all-packages pre-commit install --install-hooks --hook-type pre-commit --hook-type commit-msg
```

The root development group contains contributor tools; each package's development
group declares its own test dependencies. Commit `pyproject.toml` changes together
with the lockfile generated by uv. Do not edit `uv.lock` by hand.

## Make a change

- Support Python 3.10–3.14 on Linux and Python 3.12 on macOS.
- Keep modules in `libs/<package>/src/` and tests in `libs/<package>/tests/`.
- Use Ruff for formatting/linting and ty for type checks. Shared policy lives in
  the root `pyproject.toml`; documented package exceptions should shrink over time.
- Test observable behavior with deterministic, offline tests. Live VOSpace tests
  are a separate, explicitly requested activity.
- Keep vosfs at its configured 90% branch coverage floor.
- Update the relevant public documentation in `docs/user/` with behavior changes.
  Package design notes remain beside the package; ADRs live in `docs/adr/`.
- Do not commit generated documentation, build artifacts, or environments.

## Validate

Before opening or updating a PR, run the full gate:

```bash
uv lock --check
uv run --locked --all-packages pre-commit run --all-files
uv run --locked pytest tests/repo
uv run --locked --package vosfs pytest libs/vosfs/tests
uv run --locked --package fss-cli pytest libs/fss-cli/tests
uv run --locked --all-packages python libs/fss-cli/tests/_installed_wheel_gate.py
uv run --locked --all-packages zensical build --strict --clean
uv build --no-sources --all-packages
uv run --locked twine check --strict dist/*
```

The installed-wheel gate builds both packages, rebuilds their wheels from sdists,
and exercises isolated installs outside the checkout. Ordinary pytest runs skip
those distribution-only tests intentionally; run the gate to exercise them.

If a hook changes files, review and stage those changes, then rerun it. Never use
`--no-verify`. CI's `Required` job waits for quality, both package test matrices,
and the installed-artifact gate. A package-test failure must block merging.

## Commits and pull requests

Use [Conventional Commits](https://www.conventionalcommits.org/):

```text
fix(vosfs): handle missing node properties
feat(fss-cli): add an observable command behavior
ci(repo): require both package suites
```

Allowed scopes are `vosfs`, `fss-cli`, and `repo`; comma-separate several.
Use `!` and a `BREAKING CHANGE:` footer for breaking changes. Human contributors
can use `uv run cz commit`; automation can supply the message directly while
retaining the commit hook.

Explain the change and validation in the PR description, then obtain required
CI and review. The initial history migration requires a merge commit; squashing
or rebasing it would disconnect the imported development history from main.

## Releases

[Publishing setup](docs/releases.md) describes the dependent publishing PR and
the post-merge activation requirements.
Keep historical `v*` and `fsspec-cli-v*` tags unchanged; future releases use
`vosfs-vX.Y.Z` and `fss-cli-vX.Y.Z`.
